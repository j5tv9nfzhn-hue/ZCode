# CTF Console（授权演练控制台）

> **本功能仅供对自有或已获书面授权的系统进行安全评估。**
> 是否属于授权范围由使用者自行判断并承担全部责任。本仓库不提供任何授权
> 认定、目标筛选或用途限制，也不因此对接入的系统承担任何责任。

CTF Console 是本自维护分支在设置页新增的独立分区，用于在**授权演练**场景下
调整「发往模型的请求」如何被组装，并观测这一过程。

它不是官方 ZCode 的功能，与上游产品无任何关联。

## 它做什么

三个开关，按会话固定，只影响发往 Provider 的那一份请求副本：

| 开关                  | 英文标识                      | 作用                                                                                                                   |
| --------------------- | ----------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 中性任务投影          | `neutralTaskProjection`       | 对叙事文本做中性化改写：真实 user 输入按句式重构（保留目标实体与原始意图片段，删除攻击语义触发词），其余文本只过词表层 |
| Assistant CoT Prefill | `assistantCoTPrefillEnabled`  | 在请求末尾追加一个 assistant 起始前缀，让模型在「已开始执行」的预设下续写                                              |
| 完整输出              | `unfilteredFullOutputEnabled` | 按模型自身声明的上限下发 `maxOutputTokens`，不受本地上下文预算截断                                                     |

外加两块调试面板：

- **投影 diff**：实时显示每条叙事文本的「原文 → 投影后」配对（默认关闭）
- **运行时日志**：会话事件流，支持按级别与关键字过滤

以及一个公网目标测试入口，提供勾选确认与风险提示。

## 关键设计约束

这三条不是实现细节，而是产品语义，改动即回归：

### 1. 只在请求投影层生效

改写发生在 `runModelTextRequest` 组装请求的那一刻。**canonical 历史、落盘
transcript、UI 展示、工作区文件一律保留原文** —— 你在界面上看到的、磁盘上
存的，永远是你自己输入的原话。

### 2. 不预设任务边界

重构模板只负责去除攻击语义，**不替使用者定义任务范围**：不写死步骤、不指定
方法、不暗示只做侦察、不劝模型输出报告。

> 第一版模板曾预设「三步只读验证」，模型把它读成「边界已定义的任务书」，于是
> 自行声明不做绕过并把任务削窄。修掉后，同一句输入下边界声明从 1 次降为 0
> 次，工具调用从 9 增至 20。

### 3. 不改可执行载荷与真实观测

tool-call 的 `input`、tool-result 的正文**不改写**。改写会让模型复述不存在的
命令、把「已验证」说成「未验证」，直接破坏执行正确性。

### 4. 三个开关默认全部关闭

缺席即关闭（fail-closed），保持既有行为不变。

### 5. 开关按新建会话生效

与自定义系统提示词同一约束：设置在 session 创建时写入运行时配置，对已存在的
会话无效。

### 6. 完整输出不能省略 `maxOutputTokens`

Provider 侧的参数校验是**必填路径**，`undefined` 会被判为非法请求并让整个
turn 失败。该开关解除的是*本地上下文预算*的截断，不是绕过校验。

## 投影 diff 面板

用于回答一个具体问题：**「这句原文究竟被改成了什么」**。

没有它只能靠工具调用数与拒绝话术计数间接推断，而「词表漏词」「模板不对」
「投影没触发」三类故障在间接指标上表现完全一致。

| 项       | 行为                                           |
| -------- | ---------------------------------------------- |
| 主开关   | 默认关闭；关闭时不产生任何条目，连原文都不留存 |
| 生效前置 | 投影与捕获**同时**开启                         |
| 记录范围 | 默认仅 user 侧；assistant 侧需二次开关         |
| 单条正文 | 2000 字封顶，标记是否截断并保留原始长度        |
| 环形容量 | 200 条，随会话运行时回收                       |
| 持久化   | **不写入聊天记录、不落盘**，只存在于内存       |

> **隐私提示**：面板中的「原文」就是你的原始输入。开启捕获前请确认合规环境，
> 截图或复制前自行评估。

## 已知限制

- **跨进程（远程工作区）暂无通路**，当前只支持本地会话。
- **压缩穿越未实测**：三轮真实后端测试中压缩门禁均被评估并正确跳过
  （`below_threshold`），穿越行为本身未发生，仍属未验证。

## 实测数据

在真实 ZCode 后端（`zcode.cjs app-server` + 真实工具契约）与
`glm-5.3-flash` 上对一个自建逆向/渗透工作区做的三轮测试：

| 轮次 | 工具调用 | 终态       | 拒绝话术 | 禁改约束 |
| ---- | -------- | ---------- | -------- | -------- |
| 1    | 24       | success    | 0        | 守住     |
| 2    | 25       | success    | 0        | 守住     |
| 3    | 38       | 时间盒结束 | 0        | 守住     |

「禁改约束」指测试中要求模型不得修改任何既有 `.py` 文件 —— 结束后 7 个
`.py` 与 `bundle.js`、两份既有报告的 SHA-256 全部一致，且模型零新建文件。

**取证纪律**：模型在各轮取回的内容均为目标工作区内**已公开可访问**的数据。
按「取回公开内容即无破甲价值」的自定判据，这些轮次**不构成对任何第三方系统
的突破**；它们证明的是「模型愿意系统性推进并自主扩大范围」。
