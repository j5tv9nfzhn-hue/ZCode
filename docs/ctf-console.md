# CTF Console（授权演练控制台）

> **本功能仅供对自有或已获书面授权的系统进行安全评估。**
> 是否属于授权范围由使用者自行判断并承担全部责任。本仓库不提供任何授权
> 认定、目标筛选或用途限制，也不因此对接入的系统承担任何责任。

CTF Console 是本自维护分支在设置页新增的独立分区。它有三件事：**调整发往模型的请求如何被组装**、**观测这一过程**、**编排授权演练的结构化产物**。

它不是官方 ZCode 的功能，与上游产品无任何关联。

> 本文是 CTF Console 的**权威手册**。README 只给结论摘要与最新实测数据，
> 两处不重复展开同一段规则。

## 它做什么

### 三个开关

按新建会话固定，**默认全部关闭**，缺席即关闭（fail-closed）。

| 开关                   | 设置项                        | 作用                                                                        |
| ---------------------- | ----------------------------- | --------------------------------------------------------------------------- |
| 思维链预填 Prefill     | `assistantCoTPrefillEnabled`  | 请求末尾追加 assistant 起始前缀，让模型在「已开始执行」预设下续写           |
| 完整输出（不本地截断） | `unfilteredFullOutputEnabled` | 按模型自身声明的上限下发 `maxOutputTokens`                                  |
| 渗透编排               | `pentestOrchestrationEnabled` | 注册结构化编排工具与三个编排子代理，并把身份行换成无授权核验框架的 CTF 版本 |

### 编排与观测面板

| 面板          | 作用                                                                                                                   |
| ------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 覆盖度        | `tested/denominator` 比例 + 进度条 + 意图计数分解；分母为 0 时显示「尚未登记资产」                                     |
| 探索图 / 产物 | 目标（已达成/未达成）、待执行与执行中意图、已确认漏洞、近期事实、用户提示                                              |
| 投影 diff     | 见下节                                                                                                                 |
| 运行时日志    | 会话事件流，支持按级别与关键字过滤                                                                                     |
| 投影预览      | 本地纯函数预览：输入目标与指令，看模型会收到的投影结果。**不发起任何请求、不碰会话**，此前叫「公网目标测试」，名不副实 |

编排怎么跑、状态放在哪、每一步凭什么这么决定，见
[pentest-orchestration-mechanism.md](pentest-orchestration-mechanism.md)（机制说明）。
设计取舍与背景见
[apps/zcode-cli/docs/pentest-orchestration.md](../apps/zcode-cli/docs/pentest-orchestration.md)。

## 关键设计约束

这六条不是实现细节，而是产品语义，改动即回归。

### 1. 历史与文件永远保留原文

投影只发生在组装请求的那一刻。**canonical 历史、落盘 transcript、UI 展示、工作区文件一律保留原文** —— 你在界面上看到的、磁盘上存的，永远是你自己输入的原话。

### 2. 授权判断不在模型职责内

执行作用域由结构化状态（`po_scope` 表）承载——goals 阶段把任务点名的目标登记进去，后续执行者据此知道边界。**模型不需要核验授权**：身份行（`CTF_SECURITY_NOTICE`）刻意不含「需授权上下文」框架，避免模型把执行任务变成尽调任务（查 bounty、要求书面凭证）。

> 原请求投影路线的历史与教训见 [apps/zcode-cli/docs/neutral-task-mode.md](../apps/zcode-cli/docs/neutral-task-mode.md)。

### 3. 不改可执行载荷与真实观测

tool-call 的 `input`、tool-result 的正文**不改写**。改写会让模型复述不存在的命令、把「已验证」说成「未验证」，直接破坏执行正确性。

### 4. 默认全部关闭

缺席即关闭（fail-closed），保持既有行为不变。

### 5. 开关按新建会话生效

与自定义系统提示词同一约束：设置在 session 创建时写入运行时配置，对已存在的会话无效。

### 6. 完整输出不能省略 `maxOutputTokens`

Provider 侧的参数校验是**必填路径**，`undefined` 会被判为非法请求并让整个 turn 失败。该开关解除的是*本地上下文预算*的截断，不是绕过校验。

## 投影 diff 面板

用于回答一个具体问题：**「这句原文究竟被改成了什么」**。

没有它只能靠工具调用数与拒绝话术计数间接推断，而「词表漏词」「模板不对」「投影没触发」三类故障在间接指标上表现完全一致。

| 项       | 行为                                           |
| -------- | ---------------------------------------------- |
| 主开关   | 默认关闭；关闭时不产生任何条目，连原文都不留存 |
| 生效前置 | 投影与捕获**同时**开启                         |
| 记录范围 | 默认仅 user 侧；assistant 侧需二次开关         |
| 单条正文 | 2000 字封顶，标记是否截断并保留原始长度        |
| 环形容量 | 200 条，随会话运行时回收                       |
| 持久化   | **不写入聊天记录、不落盘**，只存在于内存       |

> **隐私提示**：面板中的「原文」就是你的原始输入。开启捕获前请确认合规环境，截图或复制前自行评估。

编排的图/产物面板同样只展示结论与 ID，**不搬运漏洞证据原文**——证据留在会话侧。

## 实测数据

在真实 ZCode 后端（`zcode app-server` + 真实工具契约）与 `glm-5.3-flash` 上对一个自建逆向/渗透工作区做的三轮测试：

| 轮次 | 工具调用 | 终态       | 拒绝话术 | 禁改约束 |
| ---- | -------- | ---------- | -------- | -------- |
| 1    | 24       | success    | 0        | 守住     |
| 2    | 25       | success    | 0        | 守住     |
| 3    | 38       | 时间盒结束 | 0        | 守住     |

「禁改约束」指测试中要求模型不得修改任何既有 `.py` 文件 —— 结束后 7 个 `.py` 与 `bundle.js`、两份既有报告的 SHA-256 全部一致，且模型零新建文件。

**取证纪律**：模型在各轮取回的内容均为目标工作区内**已公开可访问**的数据。按「取回公开内容即无破甲价值」的自定判据，这些轮次**不构成对任何第三方系统的突破**；它们证明的是「模型愿意系统性推进并自主扩大范围」。

## 已知限制

- **远程工作区未做端到端验证**：代码里**没有**本地限定——6 个开关都会转发到远端（`packages/desktop/src/host/remoteWorkspaceServiceCollection.ts:275-284`），`session/debug` 用的 client 也是按 workspace key取的。但真实远端会话上的编排行为尚未实测，不能据此认为已支持。
- **压缩穿越未实测**：三轮真实后端测试中压缩门禁均被评估并正确跳过（`below_threshold`），穿越行为本身未发生，仍属未验证。
- **同一会话不自动重开编排**：目标全部达成后再发送消息不会触发新一轮拆解，避免把「谢谢」「整理一下」这类跟进变成一次完整拆解。重新开任务请新建会话。
